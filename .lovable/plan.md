# BentaKo — Google Play Store Readiness Checklist

Goal: get the existing Capacitor-wrapped BentaKo app accepted by Google Play Console on first submission. Below is the complete list, split into what's already done, what I can change in the codebase/config for you, and what only you (the account owner) can do in the Play Console / outside the repo.

The current date is Sep 2026. From Aug 31, 2026, new apps must target Android 16 (API 36) or higher — BentaKo already targets API 36, so that hard requirement is met. [2](https://support.google.com/googleplay/android-developer/answer/11926878)

## B. Codebase / config changes I will make

These are real blockers or strong recommendations that live in the repo.

1. **Release signing configuration (hard blocker).** Today there is no keystore and `buildTypes.release` has no `signingConfig`, so the build is unsigned. I will:
   - Add a `keystore.properties`-driven `signingConfigs.release` block to `android/app/build.gradle`, referenced by `buildTypes.release`. The keystore file itself is generated by you (see C2) and never committed; `.gitignore` is updated to exclude `keystore.properties` and any `*.jks`/`*.keystore`.
2. **App Bundle (`.aab`) build script (hard blocker).** Google requires Android App Bundles for new apps, not raw APKs. I will add `cap:bundle` / `build:bundle` scripts to `package.json` that run `BENTAKO_APK=1 vite build && cap sync android`, then Gradle `:app:bundleRelease`, outputting `app/build/outputs/bundle/release/app-release.aab`.
3. **Privacy Policy page + public URL (hard blocker).** Play requires a live privacy policy URL. I will add a public `/privacy` route in the app rendering the policy text, plus a `public/privacy-policy.html` static copy, so the same URL works inside the app and as the Play Console link. Covers: Google sign-in (email/name), Supabase auth, local IndexedDB sales/stock, no third-party ad SDKs, no sale of data.
4. **In-app account / data deletion (policy requirement).** Play requires apps that support account creation to offer account deletion. Because BentaKo signs users in via Google/Supabase, I will add a "Delete my account" action in Settings that calls a server function to delete the Supabase auth user + their rows, and links to the privacy policy. This avoids rejection under the Account Deletion / Data Deletion policies.
5. **Backup data-extraction rules.** `allowBackup="true"` is set. For targetSdk 31+ Google expects `dataExtractionRules` and/or `fullBackupContent`. I will add `res/xml/data_extraction_rules.xml` and `full_backup_content.xml` and reference them in the manifest so backup behavior is explicit and review-compliant.
6. **Store icon / feature graphic assets.** Play needs a 512×512 store icon and a 1024×500 feature graphic. The current `icon-512.png` is 816×816 and `icon-192` is fine for the launcher, but the Play store icon should be exactly 512×512. I will generate a 512×512 store icon and a 1024×500 feature graphic and place them under `public/store/` (also usable as Play Console uploads). I will also ensure the adaptive launcher foreground has safe padding for the adaptive-icon "safe zone".
7. **Data safety in-app notes (supporting the form).** I will add a short `STORE_DATA_SAFETY.md` in the repo summarizing exactly what data BentaKo collects (email, display name, locally-stored sales/inventory), what is encrypted in transit (HTTPS to Supabase) and at rest (device local DB), and that no data is shared with third parties — this is the source of truth you copy into the Play Data Safety form (C7).
8. **`android:dataExtractionRules` + remove `allowBackup` risk** (folded into #5).
9. **Review-access notes.** Since the app requires Google login + onboarding, I will document reviewer test credentials/instructions in `STORE_LISTING.md` (you fill in real test values) so the App Access step is ready.

Note on category: BentaKo is a Business/Finance POS, not a lending app. The "utang" feature is a store-credit/IOU ledger between a storekeeper and their walk-in customer — it is not the app lending money to consumers, so it does not trigger Play's Personal Loans policy. I will add a one-line clarifier for this in the listing doc.

## C. Steps only you can do (outside the repo)

1. **Play Console developer account** — one-time $25 USD registration at play.google.com/console, with identity verification. (Already may have — confirm.)
2. **Generate the release keystore** (for B1). Run `keytool -genkeypair -v -keystore bentako-release.jks -keyalg RSA -keysize 2048 -validity 10000 -alias bentako` locally, then fill `keystore.properties`. **Back this up permanently** — lose it and you can never update the app under the same package name.
3. **Enroll in Play App Signing** — opt in during the first release; Google manages the app signing key, your upload key is what you keep. Recommended for safety.
4. **Build the AAB** using the new `cap:bundle` script (B2) on a machine with the Android SDK/JDK, then upload `app-release.aab`.
5. **Store listing content** (App content → Store listing): title, short description (≤80), full description (≤4000), category (Business), tags, contact email, privacy policy URL (B3).
6. **Upload graphic assets**: 512×512 store icon, 1024×500 feature graphic, and at least 2 phone screenshots (1080×1920 or 16:9). Phone screenshots are mandatory; tablet screenshots optional but recommended given BentaKo is tablet-friendly.
7. **Data Safety form** (App content → Data safety) — answer from `STORE_DATA_SAFETY.md` (B7). Declare "Email address" and "Name" collected for authentication, with "No" to sharing/selling and "Yes" to encryption in transit; device-stored sales/inventory is optional but declare local storage.
8. **Content rating questionnaire** (IARC) — answer to get a rating (BentaKo will land "Everyone" since it has no mature content); no fee.
9. **Target audience & children** — declare target audience 18+ (store owners), app NOT directed to children, and it does not attract children.
10. **Ads declaration** — select "No, my app does not contain ads."
11. **Government / Financial apps** — BentaKo is not a government app. For Finance/Business category confirm it does not move real money or store payment card data; it does not, so no license/registration is required.
12. **App Access** — set review access to "All functionality available" requires credentials; provide the Google test account + onboarding notes from `STORE_LISTING.md` (B9). If onboarding asks for a store name, give a sample.
13. **Privacy Policy** also referenced in the Data Safety section — same URL from B3.
14. **Select countries** — start with Philippines; widen later. Set pricing (free).
15. **Rollout** — choose Production (or Internal/Closed testing first). First release undergoes review (typically 1–3 days, up to 7).
